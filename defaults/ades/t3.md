# t3

Active when `T3CODE_THREAD_ID` is set. `sstack-dispatch ade` returns this note.

## Delegation

Read-only calls carry `interactionMode: "plan"`, so the child can't edit files and
its report arrives as its final message. Write calls carry `isolation: "worktree"`,
so the edits land in a separate checkout. Start, wait, collect and `record` per
[sstack § Delegation](../../skills/sstack/SKILL.md#delegation).

Make the payload's `delegate_task` call as given, even for a model of your own provider
where T3's own guidance would pick a native subagent: the payload carries the
routed model and the `record` line. Call `orchestrator_capabilities` once before the
first `delegate_task`.

## Browser

The `preview` tools load on demand: if they aren't loaded, search the deferred tool
list for `preview`.

1. `preview_open` the dev server URL.
2. Drive with `preview_navigate`, `preview_act` (click, type) and
   `preview_wait_for`.
3. Assert with `preview_snapshot`; use `preview_evaluate` for console or DOM
   reads and `preview_resize` for mobile widths.
4. Close the tab you opened.

The user watches the preview panel.

## Device

The `device` tools load on demand the same way.

1. `device_list`.
2. `device_open` with its `hostId` and `id`. It returns an `agent-device`
   command; run that command for every launch, tap, text entry and deep link.
3. `device_screenshot` to look.
4. `device_close` when done.

Builds and installs still go through the shell (`xcrun simctl install`,
`adb install`). Drive the screen only through `agent-device`.

## Capture

- Browser screenshot: `preview_snapshot` with `save=true` returns
  `screenshotPath`.
- Browser video: `preview_recording_start`, then `preview_recording_stop`,
  which returns the file path (50 MiB max).
- Device screenshot: `device_screenshot`.
- Device video: the `agent-device` command's recording (see its `help`).

Copy each file into the run's `media/` folder.
